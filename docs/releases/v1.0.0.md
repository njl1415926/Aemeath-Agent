# Aemeath Agent v1.0.0

Release date: 2026-08-12

## Status

This is the first production release of Aemeath Agent for a small invitation-only launch. The
release was promoted from `v1.0.0-rc.1` after the core deployment path ran successfully on a real
Ubuntu 22.04 `linux/amd64` ECS host with public DNS, trusted HTTPS, healthy API/Caddy containers,
and no public API port.

## Production Boundary

- Invitation-only, single-character, text-only, CPU-only Web product.
- One ECS host, one FastAPI container, one Caddy container, and one Uvicorn worker.
- React/Vite SPA and streaming SSE chat on the same HTTPS origin.
- Browser Cookie Sessions, CSRF protection, Argon2id credentials, password reset, and account
  administration through operator commands.
- Raw SQLite persistence with durable streaming idempotency and per-account daily usage quota.
- DeepSeek remote model calls, deterministic Context Budget, App Log, and Trace Log.
- Curated World Info keyword evidence as the active production retrieval path.

## Verified ECS Evidence

- Release commit `47ad8d4f3010a6b41102b1ff42054ef556e80635` cloned cleanly from
  `release/v1.0-rc.1` before promotion.
- Ubuntu 22.04.5 LTS, `x86_64`, Docker 29.7.2, Compose 5.4.0, Python 3.10.12.
- API image runs as `10001:10001`; Caddy image runs as `10002:10002`.
- API remained private on container port 8000 and reported healthy.
- `chat.aemeath.cloud` resolved to the ECS public address.
- Caddy served HTTP-to-HTTPS redirect, completed Let's Encrypt authorization, obtained the trusted
  certificate, and returned HTTP 200 from public `/health`.

## Deliberately Disabled

- Memory Worker and production long-term Memory.
- Local BGE-M3 and local LLM inference.
- Managed vector RAG in the dialogue path.
- GPT-SoVITS/audio output.
- Public registration, OAuth, multi-role RBAC, multi-character UI, and horizontal scaling.
- Multiple Uvicorn workers, PostgreSQL, Redis, and distributed locks.

## Operational Follow-ups

The small launch may proceed, but the operator must still complete and retain evidence for:

1. Invitation acceptance, login, Session lifecycle, streaming chat, refresh, and mobile smoke.
2. Container replacement and ECS reboot persistence.
3. D6 backup, independent verification, staging restore, and restored account/Session/message/quota
   checks.
4. D7 scheduled backup, log retention, host-health timer, disk warning, and Provider-failure
   diagnostics.

These items do not authorize enabling the systems listed under Deliberately Disabled.

## Upgrade and Security Notes

- Keep `/etc/aemeath/prod.env` and `/etc/aemeath/secrets/*` outside Git.
- Never commit Provider keys, CSRF keys, databases, JSONL logs, rendered Compose configurations, or
  generated indexes.
- Build `web/dist/` before the Caddy image; generated Web output remains excluded from Git.
- Do not expose port 8000 and do not run the `memory` Compose profile.
- Back up the SQLite database before replacing an existing deployment.

# Aemeath Agent v0.3

Release date: 2026-06-08

## Summary

v0.3 turns conversation identity and long-term memory into explicit runtime
systems while preserving the port-based architecture introduced in earlier
versions. The CLI remains the primary client, and recent conversation remains
available even when long-term memory is disabled.

## Major Changes

- Session is now a first-class object with stable `session_id`, `user_id`,
  `character_id`, lifecycle status, timestamps, and message statistics.
- CLI Session commands support creating, listing, resuming, ending, and
  archiving conversations.
- Long-term memory supports explicit remember triggers, message-window jobs,
  manual extraction, and standalone worker processing.
- Extracted memories have separate visibility scope and source provenance.
- Keyword, vector, fallback recall, and exact deduplication share the same scope
  rules.
- Memory delete and disable operations require matching user ownership.
- Prompt-run logs expose recalled memory IDs and summaries for debugging.
- UTF-8 and Chinese behavior checks cover runtime code, tests, and docs.

## Migration

Before first startup, back up:

```text
data/aemeath.db
```

`SQLiteStore` applies migrations during initialization:

- Legacy messages and memory jobs are assigned compatible Session records.
- Legacy long-term memories become `user_global`, preserving cross-Session
  recall behavior.
- Memory provenance is migrated once under
  `memory_scope_provenance_v1`.
- Recognized message references move to source provenance; memory-to-memory
  references retain their original meaning.
- Unknown legacy references are preserved and reported as runtime warnings.

Session and memory migrations are transactional and covered by idempotency and
rollback tests. The application does not create an automatic database backup.

## Configuration

Long-term memory remains opt-in:

```env
AEMEATH_ENABLE_LONG_TERM_MEMORY=true
AEMEATH_MEMORY_EMBEDDING_PROVIDER=hash
AEMEATH_MEMORY_WINDOW_SIZE=12
AEMEATH_ENABLE_MEMORY_WINDOW_EXTRACTION=true
```

Use `bge-m3` only after installing its local model runtime:

```env
AEMEATH_MEMORY_EMBEDDING_PROVIDER=bge-m3
AEMEATH_MEMORY_EMBEDDING_MODEL_PATH=.cache/huggingface/BAAI/bge-m3
```

Run queued extraction jobs:

```bash
python -m app.memory.worker
```

## Compatibility

- Character v0.2 remains the active Character format.
- World Info keyword retrieval remains the active RAG provider.
- Recent conversation remains active with long-term memory disabled.
- Existing prompt JSONL logs remain local under `.aemeath/sessions/`.
- The public controller continues to depend on ports instead of SQLite,
  embedding, or model implementations.

## Known Limits

- The hash embedding provider is deterministic development infrastructure, not
  a high-quality semantic model.
- BGE-M3 dependencies are not installed by the base package.
- Memory scope is supported by storage and retrieval, but automatic scope
  classification is not yet implemented; current automatic extraction uses
  `user_global`.
- Session-end tail extraction is not yet implemented.
- Structured production tracing, API/Web clients, LangGraph orchestration, and
  MCP adapters remain future work.
- `AEMEATH_MEMORY_VECTOR_DB_PATH` is reserved configuration; v0.3 stores memory
  embeddings in the main SQLite database.

# Aemeath Agent v1.0.0-rc.1

Release candidate date: 2026-08-11

## Status

This is the first deployment-oriented v1.0 release candidate. The application, Web client,
persistence contracts, deployment artifacts, and host operations are implementation-complete for a
small invitation-only launch. Stable `v1.0.0` remains gated on D8 validation on the selected ECS
host and public domain.

## Release Boundary

The first-release profile is:

- invitation-only, single-character, text-only, and CPU-only;
- one Ubuntu 22.04 x86_64 ECS host;
- one FastAPI container, one Caddy container, and one Uvicorn worker;
- React/Vite SPA served by Caddy on the same HTTPS origin as `/v1/*`;
- raw SQLite persistence with D6 backup/verify/restore tooling;
- DeepSeek remote model calls, Context Budget, App Log, Trace Log, and daily usage quota;
- active World Info keyword evidence, with long-term Memory and vector RAG disabled in production.

## Major Changes Since v0.3

### Browser Product Surface

- React/TypeScript/Vite login, invitation acceptance, password reset, Session navigation, and chat.
- Streaming SSE responses with stop, retry, failure, authentication-expiry, and responsive states.
- Aemeath display name, avatar, and release-candidate background isolated from application logic.

### Auth And Sessions

- Invitation-only accounts with Argon2id credentials and opaque server-side Cookie Sessions.
- CSRF protection, password changes/resets, Session revocation, and pre-auth rate limiting.
- Dialogue Session title, lifecycle, archived-history reads, and strict opaque cursor pagination.

### Streaming And Quota

- Provider-neutral streaming model port and shared `DialogueTurnEngine`.
- Durable request idempotency, exactly-once user/assistant persistence, terminal replay, and orphan
  recovery.
- Disconnect-safe SSE bridge, bounded response accumulation, first-wins cancellation, and shutdown
  ownership.
- Atomic stream/quota reservation and settlement with per-account UTC daily limits.

### Deployment And Operations

- Reproducible non-root, read-only Docker images and single-host Compose topology.
- Caddy HTTPS/static ingress, request-body limit, security headers, trusted-proxy boundary, and no
  public API port.
- Provider-free health/readiness checks and production configuration/secret preflight.
- Online SQLite backup, independent verification, crash-reentrant restore/rollback, and operator
  runbook.
- JSONL retention, Docker log rotation, nightly backup timer, host health checks, and disk/provider
  failure diagnostics.

## Deliberately Disabled

- Memory Worker and production long-term Memory.
- Local BGE-M3 and local LLM inference.
- Managed vector RAG in the dialogue path.
- GPT-SoVITS/audio output.
- Public registration, OAuth, multi-role RBAC, multi-character UI, and horizontal scaling.
- Multiple Uvicorn workers, PostgreSQL, Redis, and distributed locks.

These systems remain behind existing ports or isolated modules and do not need to be deleted for
the first launch.

## D8 Stable-Release Gate

Before tagging stable `v1.0.0`, run the selected ECS/domain staging acceptance:

1. Build and run the exact `linux/amd64` images with the production env and file secrets.
2. Verify HTTPS, certificates, CSP/security headers, body limits, Cookie/CSRF auth, and SSE.
3. Run authenticated desktop/mobile browser smoke for invite, login, Session lifecycle, and chat.
4. Verify SQLite, Caddy state, logs, and accounts survive container replacement and host reboot.
5. Create and verify a D6 backup, restore it in staging, and confirm account, Session, message,
   streaming-idempotency, and quota records.
6. Confirm nightly backup, log retention, host health, disk alerts, and Provider failure diagnostics.

Any D8 code correction produces a later RC. If no code changes are required, this commit may be
promoted by creating the stable release branch/tag after recording the external evidence.

## Upgrade Notes

- Back up `data/aemeath.db` before starting the new runtime against existing local data.
- Browser Auth, streaming, and quota migrations are strict and fail closed on schema drift.
- Do not expose port 8000; only Caddy publishes ports 80/443.
- Do not commit production env files, secret values, databases, logs, prompt snapshots, or generated
  RAG indexes.
- `web/dist/` is generated by `npm run build` and intentionally excluded from Git.

## Validation

- Backend collection: 935 tests; full suite passed with 6 environment/optional-integration skips.
- Frontend: 11 Vitest tests passed and the Vite production build completed.
- Ruff, compileall, deploy-lock validation, Python sdist/wheel build, and `git diff --check` passed.
- The built background asset is approximately 12 MB and remains a D8 page-load optimization item.
- Real ECS/Docker/domain evidence is intentionally not claimed by this RC.

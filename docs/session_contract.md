# Session Contract v0.1

## Purpose

Session is a first-class runtime object that owns one continuous dialogue history.
It provides stable identity and ownership information for messages, memory extraction,
prompt logs, future API clients, and LangGraph checkpoints.

Session is not long-term memory. A session records where an interaction happened;
memory decides separately whether information should remain user-global, character-scoped,
or session-local.

## Identity Model

```text
user_id
  -> many sessions

session_id
  -> exactly one user_id
  -> exactly one character_id in v0.1
  -> many messages
  -> many memory extraction jobs
```

Rules:

- `session_id` is the globally unique stable primary key.
- `user_id` is the owner identity supplied by the client/auth layer. The current CLI uses
  `Settings.default_user_id`.
- `character_id` is a stable Character Registry key.
- `user_id + character_id` is an ownership/filtering dimension, not the session primary key.
- A v0.1 session cannot change owner or character. Switching character creates a new session.
- IDs are opaque strings. Callers must not parse timestamps or business meaning from them.

## Public Schema

```python
SessionStatus = Literal["active", "ended", "archived"]

@dataclass(frozen=True)
class SessionRecord:
    id: str
    user_id: str
    character_id: str
    status: SessionStatus
    title: str | None
    metadata: dict[str, Any]
    created_at: str
    updated_at: str
    ended_at: str | None
    archived_at: str | None
    last_message_at: str | None
    message_count: int
```

`title` remains optional and is not generated by an LLM in v0.1.
`metadata` is JSON-compatible and may hold channel/client information, but must not contain
API keys or secrets.

Lifecycle semantics:

- `active` accepts new turns.
- `ended` represents an explicitly ended conversation. It rejects implicit turn handling but
  may be explicitly resumed.
- `archived` is hidden from normal active history and cannot be resumed in v0.1.
- `ended_at` is set when entering `ended` and cleared when explicitly resumed.
- `archived_at` is set when entering `archived`. If an ended session is archived, its
  `ended_at` may be retained as historical information.
- `message_count` counts successfully persisted user and assistant messages.
- `last_message_at` is the timestamp of the newest persisted message.

Allowed v0.1 state transitions:

```text
active -> ended
ended -> active
active -> archived
ended -> archived
```

An archived session has no outgoing transition in v0.1. If complete lifecycle audit history is
needed later, add a `session_events` stream rather than extending `SessionRecord` with one field
per historical transition.

## Session Store Port

The runtime depends on a protocol, not SQLite:

```python
class SessionStorePort(Protocol):
    def ensure_session(
        self,
        *,
        session_id: str,
        user_id: str,
        character_id: str,
        metadata: dict[str, Any] | None = None,
    ) -> SessionRecord:
        ...

    def create_session(
        self,
        *,
        user_id: str,
        character_id: str,
        title: str | None = None,
        metadata: dict[str, Any] | None = None,
    ) -> SessionRecord:
        ...

    def get_session(self, *, session_id: str) -> SessionRecord | None:
        ...

    def require_session(
        self,
        *,
        session_id: str,
        user_id: str,
        character_id: str,
    ) -> SessionRecord:
        ...

    def list_sessions(
        self,
        *,
        user_id: str,
        character_id: str | None = None,
        status: SessionStatus | None = "active",
        limit: int = 50,
    ) -> list[SessionRecord]:
        ...

    def end_session(
        self,
        *,
        session_id: str,
        user_id: str,
    ) -> SessionRecord:
        ...

    def resume_session(
        self,
        *,
        session_id: str,
        user_id: str,
        character_id: str,
    ) -> SessionRecord:
        ...

    def archive_session(
        self,
        *,
        session_id: str,
        user_id: str,
    ) -> SessionRecord:
        ...
```

`ensure_session` is the compatibility entry point:

- If the ID does not exist, create it with the supplied ownership.
- If it exists, require the same `user_id` and `character_id`.
- If ownership differs, raise `SessionOwnershipError`.
- If it is ended, raise `SessionEndedError`; only `resume_session` may reactivate it.
- If it is archived, raise `SessionArchivedError`.

This preserves current direct `AgentTurnInput` callers while making ownership enforceable.

`end_session` is idempotent for an already ended session owned by the caller.
`resume_session` accepts only an ended session with matching user and character.
`archive_session` accepts active or ended sessions and is idempotent for an already archived
session owned by the caller.

`require_session` is the read-only ownership check used by adjacent modules:

- it never creates or changes a Session;
- active and ended Sessions are accepted;
- archived Sessions are rejected by default;
- missing, cross-user, and cross-character access raises the corresponding typed Session error.

## Runtime Flow

```text
CLI / API
  -> create or resume SessionRecord
  -> AgentTurnInput(session_id, user_id, character_id)
  -> DialogueController
  -> SessionStorePort.ensure_session(...)
  -> save/read messages
  -> memory/RAG/model flow
```

`AgentTurnInput` remains backward compatible in v0.1. It is not replaced by a nested session
object.

The controller only orchestrates session validation. Session creation rules, ownership checks,
and persistence stay behind `SessionStorePort`.

## CLI Contract

The Session worker should add:

```text
/session current
/session new
/session list
/session resume <session_id>
/session end [session_id]
/session archive [session_id]
```

Startup creates a new session by default and prints its ID. Resuming a session must preserve
message history. CLI commands must only expose sessions owned by the current `user_id`.

`/session new` creates and selects a new active session but does not implicitly end the previous
session. CLI selection is client state, while `ended` is a durable lifecycle state; changing one
must not silently mutate the other. `/session end` performs the explicit transition. Resuming an
ended session reactivates it; archived sessions cannot be resumed in v0.1.

## Persistence And Migration

Add a `sessions` table:

```text
id TEXT PRIMARY KEY
user_id TEXT NOT NULL
character_id TEXT NOT NULL
status TEXT NOT NULL
title TEXT
metadata_json TEXT NOT NULL
created_at TEXT NOT NULL
updated_at TEXT NOT NULL
ended_at TEXT
archived_at TEXT
```

Required indexes:

- `(user_id, status, updated_at DESC)`
- `(user_id, character_id, status, updated_at DESC)`

Existing message databases must remain readable. Migration should backfill sessions from distinct
message `session_id` values using the existing single-character default `aemeath`, with timestamps
derived from message history. The migration must be idempotent.

`last_message_at` and `message_count` are public read-model fields, not required physical columns
in the SQLite `sessions` table. The v0.1 SQLite adapter derives them from `messages` using the
indexed `session_id`, and exposes an effective `updated_at` equal to the newest lifecycle update or
message timestamp. This keeps counts exact without coupling `MessageStore.save_message` to a
second store update or adding a cross-port transaction contract.

The public interface intentionally does not expose `touch_session`. A future high-volume adapter
may materialize these aggregates internally, provided it preserves the same `SessionRecord`
semantics. If message and session persistence later move to separate systems, use a reviewed
event/projection or unit-of-work design rather than making Controller maintain counters.

The v0.1 migration does not rebuild the `messages` table to add a SQLite foreign key. Runtime
ownership validation is mandatory; a physical foreign key can be added in a later database
migration framework.

## Memory Boundary

Memory may consume:

- `user_id` as the durable owner scope.
- `character_id` as an optional persona/relationship scope.
- `session_id` as source provenance, extraction window, and audit context.

Memory uses these scopes:

```text
user_global
character
session
```

Scope identity uses `scope_character_id` and `scope_session_id`. Provenance remains separate in
`source_session_id`, `source_job_id`, and `source_message_ids`. Session lifecycle storage does not
depend on Memory; future ended-session extraction must be coordinated by a lifecycle service or
event.

## Validation

- Session create/get/list/end/resume/archive works through the port.
- `ensure_session` is idempotent for matching ownership.
- Cross-user or cross-character reuse of a session ID is rejected.
- Direct turns against ended or archived sessions are rejected without message, prompt-log, or
  memory-job side effects.
- Existing controller tests remain compatible through `ensure_session`.
- CLI can create, list, explicitly end, resume, and archive sessions.
- Resumed sessions load prior messages.
- Session reads return exact `message_count` and `last_message_at` values.
- Existing databases are backfilled without losing messages.
- Memory extraction jobs continue using the same `session_id`, `user_id`, and `character_id`.
- `pytest` and `ruff check .` pass.

## Deferred

- Authentication and account management.
- Multi-character participants inside one session.
- Session sharing or collaborative rooms.
- LLM-generated titles.
- Web/API pagination contracts.
- LangGraph checkpoint storage.
- Physical foreign-key migration for existing message tables.
